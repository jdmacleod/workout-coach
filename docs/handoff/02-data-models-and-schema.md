# Data Models & Note Schema

## Design Constraints

Apple Notes does not reliably preserve HTML formatting across edits and sync.
All note content is treated as **plaintext**. Structure is encoded using:

- A YAML-like front matter block delimited by `---` lines
- Section headers prefixed with `##`
- Inline fields as `key: value` pairs within the front matter only

The parser never relies on HTML tags, markdown rendering, or rich formatting.

---

## Note Types

### 1. Workout Note

**Location in Notes:** `Exercise Coach / Workouts / YYYY-MM-DD <Type> — <Subtitle>`

**Filename pattern (local):** `data/workouts/YYYY-MM-DD-<slug>.md`

```
---
id: wrk-20250607-001
date: 2025-06-07
type: strength
subtype: upper
status: planned
duration_planned: 50
duration_actual:
distance_km:
avg_hr:
rpe:
mood:
soreness:
tags: push, pull, upper-body
source: generated
---

## Planned

### Main Lifts
- Bench Press: 4x5 @ 80% 1RM
- Barbell Row: 4x6

### Accessories
- Overhead Press: 3x8
- Pull-ups: 3xmax

## Completed
<!-- Fill in after the workout. Free text or match the planned format. -->

## How It Went
<!-- Free text. The assessor will parse this for RPE, PRs, notes. -->
```

**Front matter field reference:**

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | yes | `wrk-YYYYMMDD-NNN` |
| `date` | ISO date | yes | |
| `type` | enum | yes | `strength \| cardio \| hiit \| mobility \| rest \| external` |
| `subtype` | string | no | `upper \| lower \| full \| zone2 \| intervals \| yoga \| pilates` |
| `status` | enum | yes | `planned \| completed \| skipped` |
| `duration_planned` | int (min) | no | |
| `duration_actual` | int (min) | no | Filled during assess |
| `distance_km` | float | no | Cardio only |
| `avg_hr` | int | no | Cardio only |
| `rpe` | float 1–10 | no | Filled during assess |
| `mood` | enum | no | `great \| good \| neutral \| tired \| bad` |
| `soreness` | enum | no | `none \| mild \| moderate \| high` |
| `tags` | csv string | no | |
| `source` | enum | yes | `generated \| manual \| external` |

### 2. Weekly Plan Note

**Location in Notes:** `Exercise Coach / Plans / Week YYYY-Www`

**Filename pattern (local):** `data/plans/YYYY-Www.md`

```
---
week: 2025-W23
generated: 2025-06-07
status: active
training_focus: strength
weekly_volume: moderate
completion_rate:
avg_rpe:
---

## Schedule

| Day | Workout | Source | Duration |
|-----|---------|--------|----------|
| Mon | Strength — Upper Body | generated | 50 min |
| Tue | ⟳ Vinyasa Yoga | apple_calendar | 60 min |
| Wed | Zone 2 Run | generated | 40 min |
| Thu | ⟳ Reformer Pilates | apple_calendar | 55 min |
| Fri | Rest | — | — |
| Sat | Long Run | generated | 70 min |
| Sun | Mobility | generated | 20 min |

## Weekly Targets
- Total strength sessions: 2
- Total running volume: ~30 km
- Minimum rest days: 1

## Generation Notes
<!-- Rationale written by the planner at generation time -->

## Weekly Assessment
<!-- Written by coach assess at end of week -->
```

**Front matter field reference:**

| Field | Type | Required | Notes |
|---|---|---|---|
| `week` | ISO week | yes | `YYYY-Www` |
| `generated` | ISO date | yes | |
| `status` | enum | yes | `active \| complete \| archived` |
| `training_focus` | string | no | `strength \| cardio \| deload \| recovery` |
| `weekly_volume` | enum | no | `low \| moderate \| high` |
| `completion_rate` | float 0–1 | no | Filled by assess |
| `avg_rpe` | float | no | Filled by assess |


### 4. Config Note (`_Config`)

**Location in Notes:** `Exercise Coach / _Config`

This note is written by `coach setup` and read by `coach plan`. It mirrors
`config/config.toml` but holds user profile information (goals, constraints)
rather than system configuration.

```
---
name: Jason
timezone: America/Chicago
fitness_level: intermediate
---

## Goals
- Build upper body strength
- Maintain running base

## Schedule Constraints
- Available: Mon, Wed, Thu, Sat, Sun
- Max weekday session: 60 min
- Max weekend session: 90 min

## Equipment
- Barbell, rack, bench
- Pull-up bar
- Kettlebells: 16 kg, 24 kg

## Injury Notes
- Left shoulder impingement (resolved) — no behind-neck press

## Recurring External Classes
- Tuesday 07:00 — Vinyasa Yoga (60 min)
- Thursday 18:30 — Reformer Pilates (55 min)
```

## Python Dataclasses

```python
# coach/models/workout.py
from dataclasses import dataclass, field
from datetime import date
from typing import Literal

WorkoutType = Literal["strength", "cardio", "hiit", "mobility", "rest", "external"]
WorkoutStatus = Literal["planned", "completed", "skipped"]
WorkoutSource = Literal["generated", "manual", "external"]

@dataclass
class Workout:
    id: str
    date: date
    type: WorkoutType
    status: WorkoutStatus
    source: WorkoutSource
    subtype: str | None = None
    duration_planned: int | None = None
    duration_actual: int | None = None
    distance_km: float | None = None
    avg_hr: int | None = None
    rpe: float | None = None
    mood: str | None = None
    soreness: str | None = None
    tags: list[str] = field(default_factory=list)
    note_title: str | None = None
    planned_content: str | None = None
    completed_content: str | None = None
    how_it_went: str | None = None
```

```python
# coach/models/session.py
from dataclasses import dataclass
from datetime import date, time

@dataclass
class ExternalSession:
    title: str
    date: date
    start_time: time
    duration_minutes: int
    source: str           # "manual" | "apple_calendar" | "google_api" | "ics"
    calendar_name: str
    session_type: str     # "yoga" | "pilates" | "unknown"
    intensity: str        # "low" | "moderate" | "high"
    recovery_cost: int    # 1–5
```

```python
# coach/models/plan.py
from dataclasses import dataclass, field
from datetime import date

@dataclass
class WeeklyPlan:
    week: str              # ISO week: "YYYY-Www"
    generated: date
    training_focus: str
    weekly_volume: str
    workouts: list         # list[Workout]
    external_sessions: list = field(default_factory=list)  # list[ExternalSession]
    generation_notes: str | None = None
    status: str = "active"
```
