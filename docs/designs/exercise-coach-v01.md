## Vision (v0.2+ horizon — not in this plan's scope)
The tool eventually becomes the single source of fitness truth on Apple devices: every
Monday morning a launchd agent runs `coach plan`, reads last week's assessment, and drops
a plan into Notes before you've had coffee. Every workout entry takes 30 seconds from
an iPhone Home Screen widget via EC-QuickLog. The LLM never sees your data (on-device).

**v0.1 delivers:** the core `plan → workout → assess` loop. Everything else is v0.2+.

## Accepted Scope (added to this plan)

### 1. `coach status` command
**Output format:** single Rich table or one-line summary to stdout.
- Determine current ISO week (Mon–Sun, `datetime.date.today().isocalendar()`).
- Glob `data/plans/YYYY-Www.md` for current week. If not found: "No plan for current week. Run `coach plan` to generate one."
- Glob `data/workouts/YYYY-MM-DD-*.md` for current week; parse front matter for `status` field.
- Output: `Week 2026-W23 | Today: Strength — Upper Body (planned) | This week: 2/5 completed`
- Edge cases: rest day → `Today: Rest day`; multiple sessions scheduled → show first unstarted; no workout today → `Today: No session scheduled`
- Build order: implement during Phase 1 (CLI skeleton) as a stub, fill in during Phase 8 alongside `coach report`.
- `rich>=13.0` is already a declared dependency in `pyproject.toml`. No new dependency needed.

### 2. Cold-start onboarding questions in `coach setup`
Three additional questions in the interactive `coach setup` flow, after provider selection:

```
1. "How many days per week are you currently training?" → stored as fitness_days_per_week: N in _Config front matter
2. "What's your primary training goal?" (strength / endurance / general fitness / weight loss / sport-specific) → stored as primary_goal: <answer>
3. "Any injuries or limitations I should know about?" (free text, can skip) → stored in ## Injury Notes section of _Config note
```

These answers are injected into the planning prompt as additional context alongside `training-info.md`.
If the user passes `--non-interactive`, defaults are used: `fitness_days_per_week: 4`, `primary_goal: general fitness`, injuries: empty.

### 3. Rich progress spinner during inference
Wrap all LLM inference calls with a contextual status message using `rich.console.status()`.
- `coach plan`: `"Generating your weekly plan..."`
- `coach assess --workout`: `"Assessing [workout title]..."`
- `coach assess --week`: `"Generating weekly assessment..."`
- `coach setup` provider check: `"Checking provider availability..."`

The status spinner writes to stderr (Rich's default console targets stderr for status messages),
so `--verbose` stdout logging does not interleave with it.

### 4. `--verbose` debug flag
Add `verbose: bool = typer.Option(False, "--verbose", "-v", help="Show debug output")` to the Typer app callback. When enabled:
- Print each AppleScript call with script preview (first 80 chars) and timing to stderr
- Print provider selected and model name to stderr
- Print inference request character count and response character count to stderr
- Print each Notes API call (create/update/read) with title and timing to stderr
- Format: `[verbose] <label>: <value> (<duration>ms)` on stderr

## Critical Spec Gaps — BLOCKING (resolve before writing any code)

These four gaps must be resolved in the spec documents before implementation begins.
Each has a specific acceptance criterion.

### Gap 1: Swift binary path with `pipx install`
**Problem:** `PROJECT_ROOT / config.llm.swift.binary` resolves inside the pipx virtualenv,
which is read-only. Users cannot run `swift build` there.
**Fix:** Change the default binary path to `~/.local/share/exercise-coach/CoachInfer`.
`coach setup` copies `swift/` source to `~/.local/share/exercise-coach/swift/` and runs
`swift build -c release` there. The compiled binary lands at
`~/.local/share/exercise-coach/CoachInfer`.
**Files to update:** `07-configuration.md` (default `binary` value in LLMConfig), `05-inference-providers.md` (`_binary_path()` method), `08-implementation-guide.md` Phase 5 (setup command).
**Acceptance:** After `pipx install exercise-coach && coach setup`, the binary exists at
`~/.local/share/exercise-coach/CoachInfer` and `coach plan --dry-run` completes.

### Gap 2: `training-info.md` missing on first run
**Problem:** `coach plan` reads `data/training-info.md` but behavior when the file is
absent is unspecified.
**Fix:** If `data/training-info.md` does not exist, copy from
`data/examples/training-info.md` (shipped with the package) and print:
`"Copied example training-info.md to data/training-info.md. Edit it to match your training."`
**Files to update:** `03-cli-commands.md` (coach plan command description).
**Acceptance:** Running `coach plan` in a fresh directory without `training-info.md`
produces a warning and generates a plan using the example file.

### Gap 3: TOML parse error not handled
**Problem:** `load_config()` catches `ConfigNotFoundError` but a malformed `config.toml`
raises `tomllib.TOMLDecodeError`, which propagates as an unhandled exception.
**Fix:** In `load_config()`, catch `tomllib.TOMLDecodeError` and raise a
`ConfigError(f"Invalid TOML in {CONFIG_FILE}: {e}")` with `typer.Exit(code=1)`.
**Files to update:** `07-configuration.md` (config loading section).

### Gap 4: `platform.mac_ver()` on non-macOS (and unusual macOS version formats)
**Problem:** `int(platform.mac_ver()[0].split(".")[0])` raises `ValueError` on Linux
(returns `''`) and may produce unexpected results if the version format ever lacks
a `.` separator.
**Fix:** Defensive implementation:
```python
def is_available(self) -> bool:
    import platform
    ver_str = platform.mac_ver()[0]
    if not ver_str:
        return False  # Not macOS
    try:
        major = int(ver_str.split(".")[0])
    except (ValueError, IndexError):
        return False
    return major >= 26 and self._binary_path().exists()
```
**Files to update:** `05-inference-providers.md` (SwiftInferenceProvider.is_available() implementation).
